How the frontend reads this repo's data

The website (separate repository cot-report-ctl, folder cot-reports-frontend on your Mac) gets data from this repo in two different ways. COT data is downloaded by the visitor's browser straight from GitHub, with no server in between. Prices go through the website's own API server, which reads them from the Supabase database that this repo fills every night.

Worth fixing in the frontend repo: it downloads the CSVs from https://raw.githubusercontent.com/ngohamah/cot_analysis/master, the repo's old name. This works today only because GitHub redirects renamed repos. If a new repo called cot_analysis is ever created under your account, the redirect stops and every COT page fails. The fix is one line: in the frontend, set VITE_COT_DATA_BASE_URL (or the default in src/hooks/use-asset-data.ts) to https://raw.githubusercontent.com/ngohamah/cftc-cot-data-extraction-pipeline/master.

Step by step

A. COT data (blue)

  1. 1Every weekend the bot in this repo commits updated signal/<market>.csv files to master.
  2. 2Because the repo is public, GitHub serves every file as plain text at a fixed web address on raw.githubusercontent.com.
  3. 3When someone opens the website, their browser downloads one CSV per market from that address and draws the tables. The website's own server is not involved, so a new weekly commit shows up on the site within minutes (GitHub caches raw files for about 5 minutes).

B. Prices (green, orange)

  1. 4A price chart asks the website's API server for candles for one market and time range.
  2. 5If it hasn't answered the same question in the last hour, the server asks Supabase via price_bars_range(). This reads the daily bars this repo's price function saved last night.
  3. 6Backup: if the database has no rows for that market, or can't be reached, the server asks Yahoo Finance directly instead.
  4. 7The server sends the candles back, marked with where they came from (db or yahoo), and the chart draws them.

C. Watchlist (grey, not this repo)

  1. 8Visitors sign in through Clerk, an outside login service.
  2. 9The watchlist page asks the API server for (or saves) the visitor's list.
  3. 10The server reads or writes the watchlist table. It lives in the same Supabase project as the prices but belongs only to the website.

The agreement between the two repos

The website relies on these things staying the same. Change any of them here and the frontend must change too.

What this repo providesHow the website uses itWhat breaks if it changes
The repo stays public, on branch masterBrowsers download the CSVs without logging inMaking the repo private or renaming the branch: every COT page fails to load
File names in signal/, e.g. DJIA Consolidated.csvListed one by one in the frontend's src/lib/assets.ts (16 markets; MEXICAN PESO.csv is produced but not shown)Renaming a file: that market shows an error
Column order in the signal CSVs (8 columns, date first as YYYY-MM-DD)Read by position, not by heading name. The heading row itself is skipped.Reordering columns or inserting one in the middle: wrong numbers, with no error shown. Adding a column at the end is safe.
Signal words: Bullish, Bearish, Bullish Reversal, Bearish Reversal, No signalShown as labels. The frontend's list doesn't include No signal (125 rows, mostly the oldest weeks).Renaming a signal word: labels or colors may display wrongly
price_bars_range(asset, from_date, interval), with bar_date returned as textCalled by the API server's SQLChanging its name, inputs or outputs: charts quietly switch to the Yahoo backup
Asset names in price_assets (AUDUSD, GOLD, DOW…)Must match the frontend's market names exactlyA mismatch: that market's chart uses the Yahoo backup

What visitors see when something goes wrong

ProblemEffect on the website
The weekly bot didn't runStill works, but shows last week's data. The "latest report date" shows how old it is.
Nightly prices stopped updatingCharts stop at the last saved day. Nothing warns the visitor, because there are still rows, so the Yahoo backup doesn't kick in.
Supabase is down, or a market has no price rowsCharts still work, loaded from Yahoo (slower, and an unofficial service).
GitHub is downCOT tables don't load. Charts still work.
