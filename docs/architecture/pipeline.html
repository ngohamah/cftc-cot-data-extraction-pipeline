How the COT pipeline fits together

There are two separate data flows. COT data (weekly) is saved as files in your GitHub repository. Price data (daily) goes straight from Yahoo Finance into the Supabase database and never passes through your repository or your Mac. A third flow installs code: it moves no data, it sets Supabase up so the price flow can run.

Data moves along this line Code or settings get installed "Start now" signal (no data) Weekly COT flow Setup / code flow Daily price flow
Likely reason daily prices stopped updating: the 01:15 timer (step 9) reads the price function's address and password from Vault. Those two entries have to be created by hand in the Supabase SQL editor, and no workflow creates them. If they're missing, the timer still fires every night but its request goes nowhere, and nothing reports an error. The daily GitHub run (step 11) works around this, and it emails you if it fails.

Step by step

A. Weekly COT data (blue)

  1. 1Every Saturday at 06:00 UTC (and again Sunday, in case the report came out late), GitHub starts weekly-update.yml.
  2. 2pipeline.py downloads this year's and last year's CFTC zip files. Older years are already saved, so they aren't downloaded again.
  3. 3It cleans the numbers, works out the signals and writes a summary. If a new week arrived, the bot commits the updated data/, signal/, reports/ and its log to your repository. Run git pull to get them on your Mac.

B. Setup: installing code (purple)

  1. 4You merge a pull request into master.
  2. 5ci.yml checks the code (style, tests, price-function types). It runs on every push and pull request and changes nothing.
  3. 6If anything in supabase/ changed, supabase-deploy.yml starts.
  4. 7It applies any new migrations: numbered SQL files that create the tables, the read function and the 01:15 timer. Each file only ever runs once (see docs/MIGRATIONS.md).
  5. 8It uploads the latest price function code and gives the function its password (CRON_SECRET).

C. Daily prices (green)

  1. 9At 01:15 UTC the Supabase timer wakes up and reads the function's address and password from Vault.
  2. 10It asks the price function to update the last month of prices for every asset.
  3. 11Every day at 01:45 UTC, or whenever you click "Run workflow", GitHub starts price-backfill.yml.
  4. 12Its script asks the same price function to update, once per asset. It gets back only a receipt ("Gold: 22 bars"), never the prices themselves.
  5. 13You can run the same script on your Mac. It also only sends requests, and saves just a log file, logs/price_backfill.log.
  6. 14The price function downloads the daily bars from Yahoo Finance.
  7. 15It saves them in price_bars and records the attempt in price_ingest_runs. The same day is overwritten, never duplicated.
  8. 16price_bars_range() reads the stored bars back, either daily or grouped into weeks.
  9. 17The frontend's API server calls that function to draw the charts, instead of asking Yahoo on every page view.
